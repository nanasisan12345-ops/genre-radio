# Genre Radio — Web Edition

Last.fmで曲を探し、YouTubeで再生するジャンル探索ラジオです。GitHub Pagesだけで動作します。

公開URL: https://nanasisan12345-ops.github.io/genre-radio/

## 使い方

1. 公開URLを開きます。利用者のAPIキー入力は不要です。
2. ジャンルを選び「ランダム再生」。ブラウザーが自動再生を止めた場合は動画内の再生ボタンを押します。
3. 「設定・データ管理」からジャンル拡張のオン・オフやバックアップを操作できます。

## プレイリスト優先モード（試験）

「ジャズ」「クラシック」「ローファイ」ボタンで開始できます。各ジャンル3つの公開プレイリストを取得し、動画IDを直接再生します。`lo-fi hip hop`もローファイと同じ候補を使います。対応ジャンルの通常再生・次曲・再生失敗時の候補切り替えでは `search.list` を呼びません。未対応ジャンル、「Last.fmから曲を検索」、および「似た曲を聴く」は従来の検索方式です。

- 取得は `playlistItems.list` と `videos.list`。各リスト最大1000項目、50件ずつページングします。
- 非公開・埋め込み不可・日本での地域制限・ライブ配信を除外。1曲単位のラジオとして45秒〜20分の動画を対象にします。
- 動画IDでリスト間の重複を除き、選曲時には正規化した曲名＋アーティスト表記でもまとめます。表記違い・カバー・別演奏を完全には識別できません。
- 一巡するまで同じ曲を避け、直近200曲と直近5アーティストを可能な範囲で避けます。記録は実際の再生開始時に保存し、再読み込み後も継続します。候補不足時は直近曲制限を緩め、画面に表示します。
- 曲一覧は各端末で24時間キャッシュし、次回の選曲時に更新します。閉じている間の更新はありません。取得元・候補数・取得日を「曲の取得元」で確認できます。
- 更新失敗時は30日未満の保存済み一覧を使い、失敗を表示します。再試行は15分空けます。保存済みもなければ停止し、検索方式へ勝手に切り替えません。
- 再生を拒否した動画はそのタブの選曲候補から除外し、最大5動画で停止します。APIの埋め込み可判定でも、実プレイヤーで拒否される動画はあります。
- 元の動画タイトルを省略せず曲名欄に表示します。動画タイトルから推定したアーティストには表示を付け、推定情報からのLast.fmジャンル学習やアルバム検索は行いません。アーティストが分からない動画は投稿チャンネルを表示します。

2026-09-23の実API検証で、ジャズ329動画（正規化後324曲）、クラシック188動画（188曲）、ローファイ1230動画（1227曲）を取得。ジャズ250回・クラシック188回・ローファイ250回の選曲シミュレーションで曲重複と同一アーティスト表記の連続は0回でした。これは全動画を再生した結果ではなく、表記の推定精度を保証するものでもありません。

この取得検証は検索0回、プレイリスト取得43回、動画確認42回でした。一般APIの利用枠は使うため無制限ではありません。利用者間のキャッシュ共有はありません。取得元を追加する場合は `playlists.js` の `sources` を編集して検証・再公開します。

### 管理者用: YouTube APIキー

所有者の依頼により `public-config.js` にAPIキーを埋め込んでいます。YouTube用にはGoogle Cloudの既存プロジェクトに専用の「Genre Radio Pages」キーを作成し、YouTube Data API v3と公開ドメイン・ローカル確認URLに限定しています。キーを交換する場合の手順は次のとおりです。

1. [Google Cloud](https://console.cloud.google.com/)でプロジェクトを作成または選択します。
2. APIライブラリで「YouTube Data API v3」を有効にします。
3. 「APIとサービス → 認証情報 → 認証情報を作成 → APIキー」。
4. キーのアプリケーション制限を「ウェブサイト」にし、公開先の `https://nanasisan12345-ops.github.io/*` を登録します。ブラウザーは外部APIにoriginのみをリファラーとして送るため、リポジトリパスだけに限定しないでください。
5. ローカルでも使う場合は `http://127.0.0.1:4173/*` を追加します。
6. APIの制限で「YouTube Data API v3」のみに限定します。
7. `public-config.js` の `youtubeKey` を更新して再デプロイします。埋め込みキーは利用者から閲覧できるので、キーの制限を維持してください。API secret・OAuthクライアントシークレットは埋め込まないでください。

APIには利用枠があります。2026-09-23確認の[公式資料](https://developers.google.com/youtube/v3/docs/search/list)では、検索の標準枠はプロジェクト全体で1日100回です。利用者ごとの枠ではありません。実際の上限・残量はGoogle Cloudで確認してください。検索候補は各ブラウザーに7日間・最大200件キャッシュし、利用上限に達したら検索を停止します。再生履歴・お気に入りからの再生は検索APIを呼びません。

参考: [YouTube Data API公式ガイド](https://developers.google.com/youtube/v3/getting-started)

### Last.fm APIキー

以前のローカル版の `config.json` にある所有者の `lastfmApiKey` を `public-config.js` に埋め込んでいます。元の設定ファイル自体やAPI secretは公開していません。交換時は [Last.fmのAPIアカウント作成](https://www.last.fm/api/account/create)で取得したキーを `lastfmKey` に設定します。

## 引き継いだ機能

- ジャンル検索、ランダム連続再生、同じ曲を1巡するまで避ける選曲、早期スキップ学習
- YouTube再生候補の切り替え、音量・消音・曲別音量補正・ジャンル別音量保存、フェードイン
- 再生履歴、お気に入り（最大100曲）、履歴からの再生、YouTubeを開くリンク
- 類似ジャンル・類似アーティストの曲、歌詞、アルバム画像・情報、再生統計
- スリープタイマー、キーボード音量操作、JSON書き出し・取り込み

YouTube iframeを表示し、プレイヤーの再生・停止操作も利用できます。デスクトップ版の自動システム音声取得は、設定内の「音声波形の共有を開始 / 終了」に変更しています。対応ブラウザーでタブ音声を共有した場合に実波形を表示します。共有していないときのバーは再生状態のアニメーションです。

## ジャンルの自動拡張

- 同梱248項目を重複除去して247ジャンルから開始します。
- 起動時とページを開いている間、Last.fmの人気タグを1日以上の間隔で取得し、新規タグを追加します。
- 実際に再生が開始した曲とアーティストの上位タグを収集します。同じ取得元の再取得は7日間抑制します。
- 曲由来の候補は重み10以上、かつ異なる2組以上のアーティストで観測したときに追加します。
- 大文字小文字・表記揺れを統一し、個人用・所有メディア・年代など明らかな非ジャンルタグを除外します。タグからジャンルかどうかを完全に判定するものではありません。
- 追加したジャンル・探索記録はブラウザーに保存し、再読み込み後も継続します。「ジャンルを今すぐ更新」でも人気タグを確認できます。
- 自動拡張をオフにすると新しい自動取得を止めます。取得済みジャンルは保持します。

探索は各利用者のブラウザー内で行います。サイトを閉じている間の収集や、利用者間の自動同期は行いません。Pages自体のファイルを書き換える仕組みではありません。

## 保存と移行

公開版は利用中ブラウザーのサイト用ストレージに保存します。サイト側から保存フォルダを指定することはできません。ブラウザーのデータ消去前や端末変更前に「データを書き出す」でバックアップしてください。APIキーはバックアップに含みません。

取り込みは形式検証後、現データをJSONでダウンロードしてからバックアップ内の項目を反映します。元のElectron版のブラウザーデータは独立した領域のため、自動的には引き継がれません。元のアプリと設定はこの移植で変更していません。

## Windowsでローカル起動

Node.js 22以上が必要です。`run.bat` をダブルクリックします。依存インストールは不要です。

EdgeまたはChromeがProgram Filesにあればアプリ用ウィンドウを開きます。そのプロファイル・キャッシュは `web/Data/Browser` と `web/Data/Cache` に保存します。終了後にこのフォルダを削除すればローカルデータも削除できます。通常のブラウザーでURLを開いた場合は、そのブラウザー自身の保存先が使われます。

開発用: `npm start` → http://127.0.0.1:4173/

ローカルサーバーは静的ファイルの配信用で、APIの代理通信は行いません。公開版はNode.js不要です。

## テスト・配布・公開

```powershell
npm ci --cache Data/npm-cache
npm test
npm run build
npm run stage:pages
```

Windowsの企業証明書環境でnpmに証明書エラーが出る場合、Node.jsの対応版で `$env:NODE_USE_SYSTEM_CA='1'` を設定します。証明書検証を無効にはしません。

毎回、新しい `releases/pages-日時/` に公開ファイルだけを出力します。Data、旧Electronアプリ、node_modules、テストは含まれません。所有者が指定した公開用APIキーは `public-config.js` に含まれます。

公開はPages標準のブランチ方式（mainブランチの `/docs`）。修正後に `npm test` と `npm run stage:pages` を実行してから、変更をコミット・pushすると公開されます。`stage:pages` は新しい配布フォルダを作成し、その内容をdocsへ反映します。ワークフロー登録権限は不要です。Actions用の構成例は `scripts/pages-workflow.yml` に残しています。

Node組み込みテストでジャンル学習・永続化・APIエラーを検証。jsdomでAPI/YouTubeプレイヤーを模擬して再生状態・履歴・お気に入り・音量・歌詞・統計・タイマー・停止競合を検証しています。模擬試験は実YouTube音声再生の確認ではありません。
